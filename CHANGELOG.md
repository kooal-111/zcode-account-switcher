# Changelog

## 1.7.0-beta.5 — 2026-11-04

### Исправлено
- **«HTTP 400: captcha verify failed» при получении пакета.** Флаг сервера
  `skip_model_request` относится к проверке МОДЕЛЬНЫХ запросов, а не к клеймам:
  claim с пустым captcha-параметром сервер отклоняет. Теперь окно проверки всегда
  проходит настоящий SDK-префлайт (тихая traceless-верификация, при необходимости —
  ручная капча), и клейм отправляется с валидным параметром — ровно как в клиенте
  Z Code (префлайт `send_preflight` перед POST claim).
- Серверные ошибки клейма переводятся понятно: «captcha verify failed» →
  «Капча не пройдена — повторите получение», «security verification» → отдельный
  текст (как в апстриме 1.7.1).

### Проверено
- Живой замер: POST claim без параметра → HTTP 400 «captcha verify failed»;
  конфиг сервера при этом `skip_model_request: true` — семантика флага
  перепроверена по коду клиента Z Code 3.17.x (asar).
- cargo test 26, vitest 19, Playwright 9, clippy -D warnings, fmt, npm audit 0.

## 1.7.0-beta.4 — 2026-11-04

- Добавлен второй официальный канал обнаружения акций `marketing/touch` с возрастающим `seq`: акции, которые Z Code показывает баннером или всплывающим окном, теперь попадают в список доступных пакетов даже при пустом `billing/preview`, а старый пустой ответ marketing не переиспользуется.
- Показ, автоматическое получение и финальная проверка перед получением используют один объединённый список, поэтому marketing-only акция не исчезает между интерфейсом и отправкой claim.
- Activation-телеметрия теперь отправляется с авторизацией и теми же клиентскими заголовками, что Z Code 3.17.2; старый анонимный кэш beta.3 безопасно инвалидируется один раз.
- Канал клиента исправлен на актуальный `production`; ошибки второго канала больше не маскируются состоянием «акций нет».

## 1.7.0-beta.3 — 2026-11-03

Совместимость: Z Code 3.14–3.17.x (проверено на 3.17.2).

### Исправлено
- **Акции, появившиеся в течение дня, больше не пропускаются**: кэш активации
  разделён на `app_launch` и `app_daily_active`. Раньше успешная проверка утром
  блокировала оба события до полуночи, поэтому акция, включённая сервером позже,
  не появлялась ни в счётчике, ни в авто-получении.
- `app_daily_active`, как и в официальном клиенте, остаётся не чаще раза в сутки,
  а `app_launch` при пустом preview можно безопасно повторить через 10 минут.
  После любого успешно отправленного события выполняется повторный read-only preview.
- Стартовая и фоновая проверка теперь используют тот же activation-aware путь,
  поэтому акция обнаруживается и при выключенном авто-получении. Если все нужные
  activation-события завершились ошибкой, UI показывает ошибку и кнопку повтора,
  а не ложное состояние «пакетов нет».
- Кэш v1 мигрируется без потери дневной дедупликации и без хранения `user_id` или
  `deviceMid` в открытом виде; после обновления первый цикл сразу снимает старую
  суточную блокировку `app_launch`.

## 1.7.0-beta.2 — 2026-11-02

Совместимость: Z Code 3.14–3.17.x (проверено на 3.17.1).

### Исправлено
- **Клеймы снова видны без ручных действий**: preview доступных пакетов запускается
  автоматически при старте, после сохранения/добавления/переключения аккаунта, после
  получения пакета и по TTL (5 минут). Раньше плашка появлялась только после
  «Обновить права» или авто-получения.
- **Состояния клеймов различаются**: «не проверено» / «проверяем» / «есть пакет» /
  «нет пакетов» / «ошибка + повторить» / «данные обновляются». Раньше «не проверено»
  и «пусто» выглядели одинаково.
- Очередь preview: максимум 2 запроса одновременно с паузой 350 мс — меньше 429
  при большом числе аккаунтов; повторные ответы с устаревшим requestId игнорируются.
- CAPTCHA: таймаут и ретраи загрузки SDK, таймаут отправки без небезопасной
  повторной отправки claim, защита от двойной отправки, закрытие окна отменяет
  ровно свою попытку claim.
  Убран безусловный `--no-proxy-server` — системный/настроенный прокси больше не
  отключается (важно для капчи и входа за прокси).
- Активационная телеметрия — не чаще раза в сутки на (аккаунт, хэш deviceMid,
  версия клиента); передаётся реальное разрешение экрана и `ui_mode: code`.
- Коды ответов сервера принимаются и числом, и строкой (`0`/`"0"`/`1001`/`"1001"`).
- Блокирующие сетевые вызовы вынесены из async-команд Tauri в `spawn_blocking`
  — интерфейс больше не подвисает на запросах.
- Захватывающая капчу попытка атомарно резервируется и защищена claim_id:
  параллельный старт, чужую или отменённую капчу сдать нельзя; сверхбыстрый
  результат не теряется между стартом и установкой ожидания во фронтенде.

### Изменено
- Структурированные гранты: строки с китайскими периодами больше не формируются
  в Rust — локализация полностью во фронтенде.
- Зависимости: Tauri 2.12.x, Vite 8.3.5 (rolldown/oxc), Node >= 20.19.
  npm audit: 0 уязвимостей (было 2 high + 1 moderate).
- Качество: clippy `-D warnings` чист, cargo fmt, vitest (19 тестов),
  Playwright UI-тесты (9 сценариев: размеры 520×640/680×820/900×700, локали,
  зум 125/150%, клавиатура), cargo test — 20 тестов, фикстуры API без реальных данных.
- CI: полный набор проверок (i18n, vitest, build, npm audit, fmt, clippy, cargo test,
  cargo audit, Playwright); логи падений — в artifacts, а не в ветку.

### Безопасность
- deviceMid в кэше активаций только как sha256-ключ; токены в логах/диагностике
  отсутствуют; `ZSW_DUMP_PREVIEW=1` печатает только код ответа и массив планов.

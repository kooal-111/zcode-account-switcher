# Контрибьюторам

Спасибо за интерес к проекту! Ниже — короткое руководство, как запустить проект локально и отправить изменения.

## Требования

- **Node.js ≥ 18** (рекомендуется LTS 20.x)
- **npm ≥ 9** (поставляется с Node.js)
- ОС: **Windows 10/11** (инструмент читает `%USERPROFILE%\.zcode\v2\` и управляет процессом `ZCode.exe`)
- Установленный клиент **ZCode** (для реальной работы переключения)

## Быстрый старт (разработка)

```cmd
:: 1. Клонировать репозиторий
git clone <repo-url>
cd zcode-account-switcher

:: 2. Проверить CLI (без зависимостей)
node src\cli.js status
node src\cli.js quota

:: 3. Десктоп в режиме разработки (установит зависимости + запустит Vite + Electron с горячей перезагрузкой)
Запуск_разработка.bat
::   или вручную:
::   cd desktop && npm install && npm run dev
```

Первый запуск `npm install` в `desktop/` скачывает Electron (~100 МБ). Если скачивание падает, используйте зеркало:

```cmd
set "ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/"
cd desktop && npm install
```

## Сборка

```cmd
:: Собрать фронтенд (desktop/dist-renderer/index.html) для production
npm run build

:: Запустить готовую сборку Electron
Запуск_приложения.bat

:: Быстрый запуск без переустановки (после первого Запуск_приложения.bat)
Быстрый_запуск.bat
```

## Структура кода

| Каталог | Назначение |
|---------|-----------|
| `src/` | Бэкенд: общая логика для CLI и десктопа (CommonJS, без зависимостей) |
| `desktop/` | Electron-приложение (главный процесс + React-фронтенд) |
| `desktop/renderer/` | React + Vite фронтенд (компоненты, стили) |
| `desktop/main.js` | Главный процесс Electron: окно + IPC |
| `desktop/preload.js` | Безопасный мост contextBridge |

Ключевые модули `src/`:
- `paths.js` — пути к `.zcode/v2/` и `ZCode.exe`
- `fingerprint.js` — декодирование JWT → `user_id` как отпечаток аккаунта
- `manager.js` — CRUD снимков (list/capture/use/delete/rename)
- `switcher.js` — обнаружение процесса, бэкап, атомарная замена, откат
- `accountHealth.js` — диагностика читаемости снимка
- `oauth.js` / `oauthCli.js` — OAuth-поток добавления аккаунта
- `cli.js` — маршрутизация CLI-команд

## Стиль кода

- **CommonJS** (`require`/`module.exports`) во всём проекте — не используйте ESM-импорты.
- Сообщения пользователю и комментарии — **на русском**.
- Тексты в `console.log`/`throw`/IPC — тоже на русском (это видит пользователь).
- В `desktop/renderer/` (React) — JSX, без TypeScript.
- Селекторы CSS по BEM-подобной схеме (`.account-card`, `.account-card.current`).

## Перед отправкой PR

1. Убедитесь, что CLI работает: `node src/cli.js status` корректно показывает аккаунты.
2. Убедитесь, что десктоп собирается: `npm run build` без ошибок.
3. Проверьте, что **не закоммитили** чувствительные данные:
   ```cmd
   :: НЕ должно быть ничего в выводе
   git status --porcelain accounts/ .last/ browser_profile/
   ```
4. Не добавляйте `console.log` для отладки в финальном коде — используйте `logErr()` в `desktop/main.js`.

## Сообщить о баге / предложить идею

1. Проверьте, что баг воспроизводится на последней версии `main`.
2. Откройте issue с шаблоном:
   - **ОС**: Windows 11 / 10
   - **Версия Node**: `node -v`
   - **Шаги воспроизведения**
   - **Ожидаемое поведение** vs **фактическое**
   - **Логи**: если есть `desktop/main.log` — приложите (без токенов!)

## Безопасность

- **Никогда** не коммитьте содержимое `accounts/`, `.last/`, `browser_profile/` — там токены и сессии.
- Не вставляйте реальные токены/JWT в issue или PR — заменяйте на `***`.
- Если нашли уязвимость, связанную с безопасностью аккаунтов, — пишите приватно, не в публичный issue.

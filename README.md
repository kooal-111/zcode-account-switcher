# ZCode — переключатель аккаунтов (zcode-account-switcher)

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Node](https://img.shields.io/badge/node-%E2%89%A518-green)](https://nodejs.org/)
[![Platform](https://img.shields.io/badge/platform-Windows-blue)](#требования)

**Визуальный** инструмент для переключения аккаунтов ZCode с **десктопной версией (Electron GUI)** и **CLI-версией**. **Переключает аккаунт ZCode в один клик**, избавляя от необходимости каждый раз проходить OAuth + ввод кода подтверждения.

## Сценарии использования

- Частое переключение между несколькими аккаунтами ZCode.
- Нет желания повторять OAuth-авторизацию и ввод кода подтверждения.
- Управление локальными снимками аккаунтов через графический интерфейс.
- CLI для скриптов или быстрой диагностики.

| **ZCode клиент** | любой актуальный | Реальное переключение аккаунтов |

### Вариант 1 — Скачать готовый релиз (проще всего)

1. Скачайте ZIP-архив последнего релиза со страницы [Releases](../../releases) и распакуйте.
2. Дважды кликните **`Запуск_приложения.bat`**.
   - При первом запуске скрипт **автоматически** установит зависимости (`npm install`) и соберёт интерфейс (`npm run build`).
   - Это занимает несколько минут и скачивает Electron (~100 МБ).
3. Готово — откроется окно приложения. Дальнейшие запуски через тот же `Запуск_приложения.bat` или **`Быстрый_запуск.bat`** (мгновенно, без проверок).

> ⚠️ Если скачивание Electron падает, используйте зеркало (см. раздел [Решение проблем](#решение-проблем) ниже).

### Вариант 2 — Запуск из исходников (для разработчиков)

```cmd
:: 1. Клонировать репозиторий
git clone <repo-url>
cd zcode-account-switcher

:: 2a. Запуск CLI (мгновенно, без зависимостей)

node src\cli.js quota

:: 2b. Десктоп в режиме разработки (горячая перезагрузка Vite)
Запуск_разработка.bat
::   эквивалентно:  cd desktop && npm install && npm run dev

:: 2c. Или собрать production-сборку и запустить
```

### Вариант 3 — npm-скрипты

В корне `package.json` доступны скрипты:

```cmd
npm run status     :: текущий аккаунт + список
npm run quota      :: квота текущего аккаунта
npm run build      :: собрать десктоп-фронтенд (desktop/dist-renderer/)
npm run desktop    :: запустить Electron
npm run desktop:dev :: Vite + Electron в режиме разработки
```

### Первое использование (пошагово)

1. **Войдите в ZCode** под основным аккаунтом (обычный вход через приложение).
2. **Сохраните снимок** этого аккаунта одним из способов:
   - **GUI:** нажмите «+» в правом верхнем углу → введите имя → «Сохранить».
   - **CLI:** `node src\cli.js capture --name "Основной"`.
3. **Повторите** для каждого аккаунта: выйдите из ZCode → войдите под другим аккаунтом → capture.
4. **Переключайтесь:**
   - **GUI:** кликните по карточке аккаунта → подтвердите.
   - **CLI:** `node src\cli.js use 2` (по номеру) или `node src\cli.js use a869` (по id/префиксу).

## Решение проблем

<details>
<summary><b>Electron не скачивается / npm install падает</b></summary>

Используйте китайское зеркало (быстрее в Азии) или официальное:

```cmd
:: Вариант A — зеркало npmmirror
set "ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/"
cd desktop && npm install

:: Вариант B — полный registry-зеркало
npm config set registry https://registry.npmmirror.com
cd desktop && npm install
```
</details>

<details>
<summary><b>Окно Electron не появляется</b></summary>

1. Проверьте переменную окружения — она должна быть пустой:
   ```cmd
   echo %ELECTRON_RUN_AS_NODE%
   :: должно быть пусто. Если нет:
   set "ELECTRON_RUN_AS_NODE="
   ```
2. Посмотрите `desktop\main.log` — там пишутся ошибки главного процесса.
3. Запустите через `Быстрый_запуск.bat` — он выводит лог Electron прямо в консоль.
</details>

<details>
<summary><b>«Не удалось определить текущий аккаунт» в status</b></summary>

В текущем `config.json` нет provider с открытым JWT `apiKey` (всё зашифровано `enc:` или нет входа). Переключение всё равно работает, но отпечаток определяется слабо. Решение: сделайте `capture` каждого аккаунта, когда хотя бы один provider с открытым `apiKey` активен.
</details>

<details>
<summary><b>После переключения ZCode показывает старый аккаунт</b></summary>

ZCode не был перезапущен. Убедитесь, что `status` показывает «запущен» перед `use` — тогда `use` автоматически закроет и перезапустит клиент. С флагом `--no-restart` нужно перезапустить вручную.
</details>

## Принцип работы

Сессия входа ZCode хранится в двух файлах (Windows):

| Файл | Содержимое |
|------|------------|
| `%USERPROFILE%\.zcode\v2\credentials.json` | `enc:v1:...` зашифрованный OAuth-токен (`oauth:zai:access_token` / `zcodejwttoken` / `oauth:zai:user_info`) |
| `%USERPROFILE%\.zcode\v2\config.json` | `apiKey` в каждом разделе provider (открытый JWT, base64 payload содержит `user_id`) |

Эти два файла вместе = **полная сессия входа**. Что делает инструмент:

1. **capture**: сохраняет оба файла целиком как «снимок аккаунта»
2. **use**: закрывает ZCode → создаёт резервную копию текущей сессии в `.last` → **атомарно заменяет** оба файла снимком → перезапускает ZCode
3. Идентификация аккаунта (отпечаток) — извлечение `user_id` из `apiKey` JWT активного provider в `config.json`, дедупликация и именование

Суть переключения — «замена файлов сессии + перезапуск», поэтому это **бесшовное переключение** — не нужно сканировать QR-код или вводить код подтверждения.

## CLI-версия (командная строка · резервная)

Требуется только Node.js ≥ 18, **без зависимостей** (без `npm install`).

```cmd
cd zcode-account-switcher
node src/cli.js status
node src/cli.js quota
```

В корневом каталоге также есть npm-скрипты:

```cmd
npm run status
npm run quota
npm run build
npm run desktop
```

Опционально: создайте алиас (добавьте в PowerShell `$PROFILE`):
```powershell
function zcas { node "<путь_к_проекту>\zcode-account-switcher\src\cli.js" @args }
```
После этого можно использовать `zcas status` / `zcas use 1`.

## Рабочий процесс

### Первый раз: сделайте capture для каждого аккаунта

После входа в ZCode под каждым аккаунтом, в **состоянии входа** выполните:

```cmd
node src/cli.js capture --name "Основной аккаунт"
```

Затем выйдите из ZCode → войдите под другим аккаунтом → снова capture:

```cmd
node src/cli.js capture --name "Доп. аккаунт A"
```

Повторяйте, пока все аккаунты не будут сохранены.

### Повседневное переключение

```cmd
:: Посмотреть текущий аккаунт + список
node src/cli.js status

:: Переключиться на аккаунт №2 (автоматически закрыть и перезапустить ZCode)
node src/cli.js use 2

:: Или по id (поддерживается префикс, напр. a869)
node src/cli.js use a869
```

### Если при переключении возникла проблема

```cmd
:: Откатиться к сессии до переключения (из резервной копии .last)
node src/cli.js rollback
```

## Список команд

| Команда | Действие |
|---------|----------|
| `status` | Показать текущий аккаунт + список сохранённых (команда по умолчанию) |
| `list` | Показать все сохранённые аккаунты |
| `quota` | Показать квоту текущего аккаунта (всего, использовано, осталось, по позициям) |
| `capture [--name имя] [--note заметка] [--overwrite]` | Сохранить текущую сессию как снимок (при совпадении имени добавить `--overwrite`) |
| `use <id\|номер> [--no-restart] [--force]` | Переключить аккаунт (по умолчанию автоматически перезапускает ZCode; `--no-restart` только заменяет файлы) |
| `delete <id\|номер>` | Удалить снимок аккаунта |
| `rename <id\|номер> <новое_имя>` | Переименовать |
| `rollback [--no-restart]` | Откатиться к сессии до переключения (`.last`) |
| `kill` / `launch` | Вручную закрыть / запустить ZCode |

`<id|номер>` поддерживает как номер из списка (`1`/`2`/`3`), так и короткий id аккаунта, а также префикс id (например, `a869` найдёт `a869314f`).

## Механизмы безопасности

- **Перед переключением ZCode должен быть закрыт**: изменение файлов сессии в работающем клиенте ненадёжно (клиент перезапишет изменения). Инструмент автоматически закрывает сессию при `--force`; без флага — отказывается переключаться с предупреждением.
- **Автоматическое резервное копирование**: перед каждым `use` текущие файлы копируются в `.last/`, всегда можно выполнить `rollback`.
- **Атомарная запись**: сначала запись в `.tmp`, затем переименование — чтобы избежать повреждения сессии при частичной записи.
- **Самовосстановление при ошибке записи**: если на этапе замены произошла ошибка, автоматически восстанавливает из `.last`, повреждённое состояние не остаётся.
- **Дедупликация по отпечатку**: повторный `capture` одного аккаунта выдаст предупреждение о существовании (с `--overwrite` — перезапишет).

## Часто задаваемые вопросы

**В: После переключения ZCode всё ещё показывает старый аккаунт?**
О: Убедитесь, что ZCode был закрыт и перезапущен при переключении (если `status` показывает «запущен», `use` автоматически kill+launch). При использовании `--no-restart` нужно вручную перезапустить ZCode.

**В: `status` показывает «не удалось определить текущий аккаунт»?**
О: Это значит, что в текущем `config.json` нет provider с открытым JWT apiKey (возможно, всё зашифровано `enc:` или нет входа). Переключение всё равно возможно (используя полные файлы из снимка), но отпечаток будет определён по хэшу — рекомендуется выполнять capture для каждого аккаунта при включённом provider с открытым apiKey.

**В: Токены в снимках аккаунта истекут?**
О: Да, `access_token` имеет срок действия. Но при запуске ZCode клиент автоматически продлевает токены через refresh-механизм, поэтому снимок хранит «идентичность входа», а продление — задача клиента. Если аккаунт долго не использовался и refresh тоже истёк, просто войдите заново и выполните `capture --overwrite`.

**В: Что делать при смене компьютера?**
О: Скопируйте весь каталог `accounts/` (при условии, что на новом компьютере установлен ZCode и путь `.zcode/v2` совпадает).
